# CLAUDE.md — Обиход

## Что это

Компания **«Обиход»** — комплексный подрядчик «порядок под ключ» для Москвы и МО.
Направления по целевой карте [contex/08_site_map_target.html](contex/08_site_map_target.html):
вывоз мусора · арбористика (спил и уход за деревьями) · чистка крыш и уборка снега ·
уборка территории · выравнивание и планировка участка · демонтаж и снос · дизайн ландшафта ·
доп. услуги (аренда техники, промальп, порубочный билет). B2C (частные дома, дачи) + B2B (УК, ТСЖ, FM,
застройщики, госзаказ).

**Главная цель сайта:** приносить квалифицированные заявки на услуги.

> Магазина и личного кабинета нет, товары не продаём (ADR-0020, ADR-0022).

## Как работаем

**Единственный план — [contex/09_product_plan.md](contex/09_product_plan.md)**, статусы задач —
[contex/09_product_plan-status.md](contex/09_product_plan-status.md). Процесс v1 (9 ролей, backlog,
specs, GSD) — в [archive/process-v1/](archive/process-v1/), новые задачи туда не пишем.

**Роли:** владелец (samohingeorgy@gmail.com) решает и принимает; Claude делает.

**Цикл каждой задачи:**
1. **Perplexity** — «как лучше в 2026 для РФ и наших клиентов», вывод с источниками в задачу.
2. **Решение по brand-guide**; если в нём чего-то нет — сначала дополняем его.
3. **Реализация** в отдельной ветке, небольшими PR.
4. **Автопроверки** — type-check, lint, format, e2e форм, скриншоты 360/768/1280/1440, axe, schema, ссылки.
5. **Показ владельцу** — превью и скриншоты desktop / laptop / mobile.
6. **Приёмка владельцем.**
7. **PR → main → деплой** `deploy/manual-deploy.sh <sha>` → smoke прода.

Definition of Done страницы — в плане 09, раздел 4. Решения фиксируются в журнале плана 09
(раздел 9); старые ADR в [team/adr/](team/adr/) действуют, пока план их не заменил.

## Поведенческие правила (Karpathy-derived)

### 1. Думай прежде чем кодить
- Не делай предположений молча и не прячь сомнения, озвучивай tradeoffs.
- Если есть несколько интерпретаций — покажи их; если есть путь проще — скажи.

### 2. Простота прежде всего
- Минимальный код, который решает задачу.
- Без фич сверх запрошенного, без абстракций для одноразового кода, без ненужной конфигурируемости.

### 3. Хирургические правки
- Трогай только то, что должен; соблюдай существующий стиль.
- Несвязанный мёртвый код — упомяни, не удаляй.
- Удаляй orphan-импорты, которые остались после ТВОИХ правок.

### 4. Цель-driven выполнение
- Определи критерии успеха и доведи до проверенного результата.
- Для многошаговых задач: `1. шаг → verify: проверка`.
