# ADR-0022 — Customer cabinet sunset

## Контекст

В апреле 2026 (brand-guide v2.1) заложили клиентский аккаунт: «Войти / Регистрация» в шапке,
auth-экраны (SMS / email+пароль / magic-link / 2FA, регистрация B2C+B2B), единый личный кабинет
для услуг и магазина (заявки, заказы, резервы, избранное, адреса, юрлица), коллекция Payload
`Customers`. Кабинет проектировался как «один аккаунт — две истории» (услуги + магазин).

ADR-0020 вывел магазин, но кабинет остался: в brand-guide §30-32, в живом `Header.tsx` (кнопки
«Войти» / «Регистрация» без обработчиков — вели в никуда), в CSS и макетах `newui/`. Кроме того,
ADR-0020 не добил хвосты магазина: shop-иконки в §08, «Магазин» в mega-menu §09 и footer §33,
CSS витрины / корзины / чекаута.

Оператор 2026-10-18: личный кабинет и продажу товаров не делаем, идею убираем из проекта.

## Решение

1. **Клиентских аккаунтов нет.** Ни входа, ни регистрации, ни личного кабинета, ни коллекции
   `Customers`. Вход на сайт есть только у команды — Payload `/admin` (коллекция `Users`, 2FA).
2. **Товары не продаём.** Ни каталога, ни корзины, ни оплаты. 410 Gone для `/shop*` (ADR-0020)
   остаётся.
3. **Статус заявки клиенту сообщает менеджер** — звонком или в мессенджере. Канон статусов
   (`Leads.status`, amoCRM-маппинг) живёт в brand-guide §32 «Статусы заявки» (`#lead-status`);
   номер §32 сохранён, чтобы не плодить ссылки.
4. **Header справа:** телефон + `.mm-cta` «Получить смету» → `/kalkulyator/foto-smeta/`
   (канонический CTA из brand-guide §09, который §30 когда-то заменил на auth-кнопки).

## Альтернативы

- **Оставить §30-32 как «будущее».** Отвергнуто: оператор закрыл идею; спящий раздел в
  source-of-truth провоцирует команду верстать по нему (кнопки уже попали в прод).
- **Просто удалить кнопки без замены.** Отвергнуто: на ≤1100 телефон скрыт, шапка осталась бы
  без CTA. «Получить смету» — канон §09, без новых компонентов.

## Последствия

- Плюсы: из шапки ушли нерабочие кнопки; brand-guide короче на ~1000 строк; −~1500 строк мёртвого
  CSS в бандле маркетинга; нет PII-хранилища клиентов (меньше 152-ФЗ-обязательств).
- Минусы: нет self-service статуса заявки — нагрузка на менеджера. Если понадобится, ближайший
  шаг — уведомления о смене статуса в мессенджер, а не кабинет.
- Возврат к кабинету — только новым ADR с бизнес-обоснованием.
